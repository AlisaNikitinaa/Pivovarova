## Запуск установленного сервера PostgreSQL

На компьютере установлен PostgreSQL 18 в `/Library/PostgreSQL/18`.
При проверке сервер на `127.0.0.1:5432` не отвечал, служба `postgresql-18`
не была загружена. Существующий сервер и его данные при работе над проектом
не изменялись. DBeaver является клиентом: его открытие само по себе не запускает сервер.

Проверь доступность:

```bash
/Library/PostgreSQL/18/bin/pg_isready -h 127.0.0.1 -p 5432
```

Если сервер не отвечает, загрузи установленную службу в Терминале:

```bash
sudo launchctl bootstrap system /Library/LaunchDaemons/postgresql-18.plist
/Library/PostgreSQL/18/bin/pg_isready -h 127.0.0.1 -p 5432
```

`sudo` запрашивает пароль пользователя macOS. Он отличается от пароля PostgreSQL.
Если служба уже загружена, но остановлена, вместо повторного `bootstrap` используй:

```bash
sudo launchctl kickstart system/postgresql-18
```

Продолжай после сообщения `accepting connections`. Если служба не запускается,
сохрани текст ошибки: это проблема запуска установленного сервера, а не Flask.

## Подключение своей базы

Настройки для второго и третьего семинаров находятся в одном файле:
`/Users/ivan/sem/data/db_config.json`.

В нём сохранены прежние имя пользователя, пароль и имя базы из проекта;
исправлены имя файла и ключ `password`. Проверь их соответствие своей установке.
Пример структуры (вместо текста-заглушки укажи свой пароль):

```json
{
  "host": "127.0.0.1",
  "port": 5432,
  "user": "postgres",
  "password": "ВАШ_ПАРОЛЬ_POSTGRESQL",
  "database": "supermarket",
  "connect_timeout": 3
}
```

Если используешь другую базу, измени `database`; если другой сервер или порт —
`host`/`port`. После сохранения JSON перезапусти приложение. Пароль в JSON должен
быть паролем роли PostgreSQL, а не паролем macOS.

Оба приложения выполняют запрос к таблице `product` и используют поля:

- `prod_name` — название;
- `prod_measure` — единица измерения;
- `prod_price` — цена;
- `prod_category` — категория для фильтрации.

Таблица должна быть доступна в выбранной базе через обычное имя `product`
(для демонстрационного примера это схема `public`). Категорию вводи так, как она
хранится в таблице. Для другого учебного задания понадобятся соответствующие
ему SQL-запрос и шаблон таблицы; простая смена имени базы не меняет структуру запроса.

## Если учебной базы ещё нет

Подготовлен `/Users/ivan/sem/data/setup.sql`: демонстрационная таблица и пять товаров.
Это небольшой пример для проверки приложения, а не схема или данные преподавателя.
Если у тебя уже есть учебная база, используй её вместо этого примера.

Для новой базы выполни команды по очереди:

```bash
/Library/PostgreSQL/18/bin/createdb -h 127.0.0.1 -p 5432 -U postgres -W supermarket
/Library/PostgreSQL/18/bin/psql -h 127.0.0.1 -p 5432 -U postgres -d supermarket -W -v ON_ERROR_STOP=1 -f /Users/ivan/sem/data/setup.sql
```

Команды запрашивают пароль PostgreSQL. Если `supermarket` уже существует,
первую команду пропусти. Скрипт предназначен для новой демонстрационной базы;
он не удаляет таблицы и повторно не добавляет те же пять примеров.

Проверка таблицы:

```bash
/Library/PostgreSQL/18/bin/psql -h 127.0.0.1 -p 5432 -U postgres -d supermarket -W -c "SELECT prod_name, prod_category FROM product;"
```

После этого запусти второй или третий семинар и введи в форму одну из категорий:
`молочные`, `овощи`, `хлеб`. Для `молочные` должны появиться молоко и сыр.

В DBeaver можно сделать то же самое: создать подключение PostgreSQL с указанными
host/port/database/user/password, открыть SQL-редактор выбранной базы и выполнить
содержимое `/Users/ivan/sem/data/setup.sql`. Для уже существующей учебной базы
выполнять демонстрационный скрипт не требуется.
